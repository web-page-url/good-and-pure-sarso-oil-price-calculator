# Plan 2.0: English/Hindi Language Toggle

## Context
The user wants a toggle button to switch the Sarso Oil calculator's UI into Hindi, so it's usable by shop staff/customers more comfortable reading Hindi. They asked for the toggle to sit at the top of the page. Decisions confirmed with the user: units/numbers (kg, gram, ₹) stay in English/Roman script since that's how Indian retail already reads them — only labels, hints, messages, and button text get translated; and English remains the default language on first visit, with the user's choice remembered for later visits (matching how box weight and Sarso type are already remembered).

## Deliverable
Implement the EN/Hindi toggle in the app: `index.html`, `anubhav.js`, `anubhav.css`, plus one new file `translations.js`.

## Approach
Reuse the app's existing patterns rather than inventing new ones:
- The `localStorage` save/restore pattern already used for box weight & Sarso type (`anubhav.js` `BOX_STORAGE_KEY`/`TYPE_STORAGE_KEY`, `saveLastValues()`/`restoreLastValues()`) — add a `LANG_STORAGE_KEY = 'sarso_lang'` following the same shape.
- The existing pill-toggle-button visual language already used by `#totalUnitToggle` and `#resetBtn` (`anubhav.css`) — the new language toggle gets its own `.lang-toggle` class copying that same look (rounded pill, green-deep border/text, gold-gradient hover).

### 1. New file: `translations.js`
A plain `const TRANSLATIONS = { en: {...}, hi: {...} }` object (no build step, no modules — just a global loaded via `<script>`). Keys cover every translatable string:
- Header: title, tagline
- Card titles (both calculators), reset button label + its `title` attribute
- All field labels, all 3 `.unit-hint` tip sentences, both `<select>` option labels (Hindi text keeps the literal `—` separator, e.g. `काला सरसों — ₹220 / kg`, since `calculate()` parses the Sarso name via `.split('—')[0].trim()` — value attributes 220/240 stay untouched)
- Default text for `#weightHint` and `#budgetHint`
- Breakdown labels ("Oil Weight" / "Rate" / "Per 100g"), "Total Price", "Step-by-Step Calculation" heading
- Oil-card headers ("Black Sarso" / "Yellow Sarso"), footer text
- Input `placeholder` values (3) and the unit-toggle button's `title`
- Dynamic-string fragments used inside `anubhav.js`: the two `showError()` messages, the `showWarning()` sanity-check message, the `"Rate: ₹X per kg"` phrase, and the literal words `"kg"` / `"(oil)"` / `"gram"` used inside the `step1/step2/step3` and `blackCalc`/`yellowCalc` template literals.
Units/₹/numbers are NOT translated per the user's decision — only the surrounding words.

Loaded in `index.html` before `anubhav.js`:
```html
<script src="translations.js"></script>
<script src="anubhav.js"></script>
```

### 2. `index.html` changes
- Language toggle button in `<header>`, near the top: `<button type="button" class="lang-toggle" id="langToggle" data-i18n-title="langToggleTitle">EN / हिं</button>`.
- Static text annotated with `data-i18n="key"` (sets `textContent`), `data-i18n-placeholder="key"` for input placeholders, `data-i18n-title="key"` for `title` attributes.
- Where a label mixes an icon span + plain text, the text is wrapped in its own `<span data-i18n="...">` so the icon glyph is left alone.
- Noto Sans Devanagari appended to the existing Google Fonts `<link>` so Hindi text renders with a consistent, deliberate typeface instead of an inconsistent OS fallback.

### 3. `anubhav.js` changes
- `let currentLang = 'en';` and `LANG_STORAGE_KEY = 'sarso_lang'` near the existing storage keys.
- `function t(key)` — looks up `TRANSLATIONS[currentLang][key]`, falling back to English then the raw key.
- `function applyLanguage(lang)` — sets `currentLang`, persists it, updates the toggle button's visual state, re-renders every `[data-i18n]`/`[data-i18n-placeholder]`/`[data-i18n-title]` element, then calls `calculate(); calculateBudget();` so on-screen dynamic text re-renders immediately.
- `restoreLang()` (mirrors `restoreLastValues()`), called at init before the first `applyLanguage()`/`calculate()` call.
- `langToggle` click handler flips `en`↔`hi` and calls `applyLanguage()`.
- Inside `calculate()`/`calculateBudget()`, hardcoded English fragments (error/warning messages, the rate line, the literal "kg"/"(oil)"/"gram" words) replaced with `t('key')` lookups — numbers, ₹ amounts, and math operators stay literal.

### 4. `anubhav.css` changes
- `.lang-toggle` rule set, visually matching `.unit-toggle`/`.reset-btn`.

## Verification
- Toggle language mid-calculation and confirm every visible string — including dynamically-built breakdowns — switches to Hindi immediately.
- Reload after switching to Hindi and confirm it stays in Hindi (localStorage persistence).
- Confirm the Sarso type `<select>` still computes correctly in Hindi and the step-3 breakdown still shows the Hindi Sarso name correctly (validates `—`-split parsing against Hindi option text).
- Automated headless-browser check (Playwright) to confirm no console errors and no leftover untranslated English/`undefined` text in either language.
